Q4 data migration plan

Move the orders and billing tables from the legacy Postgres 11 cluster to the new Aurora cluster with no more than 5 minutes of write downtime, finishing before the December freeze.

Scope

Three schemas move this quarter. Analytics replicas stay on the old cluster until January and read through a foreign data wrapper in the meantime.

  • orders — 1.8 TB, 412M rows, highest write volume
  • billing — 240 GB, includes the Stripe event ledger
  • catalog — 36 GB, read-heavy, safe to move first

Dana Okafor, review on v6

Cutover procedure

Run from the bastion host. The script pauses writers, waits for replication lag to reach zero, then flips the connection string in the config service.

bash# 1. Freeze writers and wait for lag to drain
./bin/cutover --schema orders --pause-writers
./bin/lag --until 0 --timeout 240s

# 2. Flip the DSN and resume
cfg set db.orders.dsn "$AURORA_ORDERS_DSN"
./bin/cutover --schema orders --resume

Rollback

If the error rate on /checkout exceeds 0.5% for two minutes, point the DSN back at the old primary. Reverse replication stays on for 72 hours after each cutover.

Before Nov 4

  • Provision Aurora cluster and parameter groups
  • Catalog dry run with row-count and checksum diff
  • Ledger replay test passes twice in staging
  • Load test checkout at 2× peak against Aurora
  • Post cutover window in #eng-announce 48 hours ahead
